# FakeSolar — MeshCore для Faketec + SX1268

Прошивки MeshCore для саморобної ноди на базі **Faketec (ProMicro nRF52840)** з радіомодулем **E22-400M22S (SX1268, 433 МГц)**, сенсорами, RTC та GPS із захистом від спуфінгу.

Конфігурація збірки: [`variants/fakesolar_sx1268/platformio.ini`](../variants/fakesolar_sx1268/platformio.ini).

## Залізо

| Вузол | Модель | Підключення |
|---|---|---|
| MCU | ProMicro nRF52840 (Faketec) | — |
| Радіо | E22-400M22S (SX1268), TCXO 1.8 В, DIO2 як RF-switch | стандартна розводка Faketec |
| Темп./вологість | AHT20 | I²C 0x38 |
| Тиск | BMP280 або BME280 (BME280 дає ще й вологість; прошивка розрізняє їх за ID чипа) | I²C 0x76/0x77 |
| Струм/напруга | INA3221, шунти CH1 0.1 Ом, CH2 0.04 Ом, CH3 0.04 Ом | I²C 0x42 |
| RTC | PCF8563 | I²C 0x51 |
| GPS | NMEA, UART (швидкість визначається автоматично) | RX=3, TX=4, EN=5 |
| Дільник батареї | 1.1 МОм до «+», 1.5 МОм до «−» | ADC пін 17 |

Шина I²C: SDA=8, SCL=7.

## Прошивки

| Файл | Роль |
|---|---|
| `Faketec_SX1268_repeater.uf2` / `.zip` | Repeater |
| `Faketec_SX1268_sensor.uf2` / `.zip` | Sensor |
| `Faketec_SX1268_companion_radio_ble.uf2` / `.zip` | Companion (BLE, PIN `123456`) |

Прошивка UF2: двічі натиснути reset → з'явиться USB-диск → скопіювати `.uf2`.
ZIP — для DFU або веб-flasher.

Радіопараметри за замовчуванням (EU 433MHz Narrow): **433.650 МГц, BW 62.5 кГц, SF 8, CR 8**. Діють при першому запуску; змінюються через `set radio f,bw,sf,cr` або застосунок.

## Що змінено відносно MeshCore

- **SX1268** у варіанті ProMicro (`USE_SX1268`).
- **INA3221**: окремий шунт для кожного каналу; напруга батареї з каналу `TELEM_INA3221_BAT_CH`; ознака заряджання за знаком струму (на цій платі плюс = заряд, інвертування вимкнене).
- **АЦП батареї**: множник `ADC_MULTIPLIER` під дільник 1.1М/1.5М, час вибірки 40 мкс (високоомний дільник). Використовується, якщо INA3221 не знайдено.
- **GPS**:
  - автовизначення швидкості UART (`GPS_BAUD_AUTODETECT`);
  - інтервальний режим як у Meshtastic (`GPS_DUTY_CYCLE`): вмикається раз на 30 хв, шукає до 300 с, вимикається одразу після достовірного fix і синхронізації часу;
  - захист від спуфінгу (`GPS_GUARD`): fix приймається лише при ≥4 супутниках, HDOP ≤ 4.0, у межах регіону (Україна), у межах геозони навколо заданої позиції ноди, без «неможливих» стрибків і після 5 узгоджених fix поспіль;
  - час із GPS пишеться в RTC лише при достовірному fix, у межах [дата збірки; +10 років] і з корекцією не більше 10 хв, якщо годинник уже валідний; після першої прийнятої синхронізації — лише в межах дрейфу кварца (5 с + 100 ppm);
  - тривога: якщо при достовірному fix GPS ≥ 60 хв стабільно розходиться з годинником (на одну й ту саму величину ±60 с), у `gps_guard` з'являється `ALERT gps-clk <зсув>`, а в телеметрії — додатковий канал зі зсувом у годинах.
- **CLI**:
  - `telemetry` — показники всіх сенсорів текстом;
  - `time force <epoch>` — виставити час навіть назад (після спуфінгу часу).

## Корисні команди CLI

```
telemetry                    показники сенсорів
power                        батарея / заряджання
gps / gps diag               стан GPS
clock                        поточний час
set lat <..> / set lon <..>  позиція ноди = центр геозони GPS
sensor list                  налаштування GPS
sensor set gps_cycle <хв>    інтервал GPS (0 = постійно)
sensor set gps_ontime <с>    макс. час пошуку
sensor set gps_fence <м>     радіус геозони (0 = вимк.)
sensor get gps_guard         стан фільтра fix і часу
sensor get gps_spoof         історія спуфінгу з моменту старту: <подій>x <хв тому>m <причина>
time force <epoch>           примусово виставити час
sensor set gps_time_accept 1 при активній тривозі: підтвердити, що правий GPS (лише та сама розбіжність, достовірний fix)
```

`gps_cycle`, `gps_ontime`, `gps_fence` після перезавантаження повертаються до значень зі збірки.

## Збірка

```bash
pio run -e Faketec_SX1268_repeater -e Faketec_SX1268_sensor -e Faketec_SX1268_companion_radio_ble
```

Debug-збірка з логами запуску (I²C-скан, GPS, радіо): `Faketec_SX1268_repeater_debug`.
