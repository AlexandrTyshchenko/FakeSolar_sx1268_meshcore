# FakeSolar — MeshCore для Faketec + SX1268

Прошивки MeshCore для саморобної ноди на базі **Faketec (ProMicro nRF52840)** з радіомодулем **E22-400M22S (SX1268, 433 МГц)**, сенсорами, RTC та GPS із захистом від спуфінгу.

Репозиторій: https://github.com/AlexandrTyshchenko/FakeSolar_sx1268_meshcore (гілка `main`). Конфігурація збірки: `variants/fakesolar_sx1268/platformio.ini`. Перелік змін і збірка з нуля — у `BUILD.md`, усі зміни одним патчем — `fakesolar.patch`.

Основа — гілка `dev` MeshCore (meshcore-dev/MeshCore), куди вже злито новий GPS-код (#3753) разом з нашим захистом від спуфінгу та автовизначенням швидкості GPS.

## Залізо

| Вузол | Модель | Підключення |
|---|---|---|
| MCU | ProMicro nRF52840 (Faketec) | — |
| Радіо | E22-400M22S (SX1268), TCXO 1.8 В, DIO2 як RF-switch | стандартна розводка Faketec |
| Темп./вологість | AHT20 | I²C 0x38 |
| Тиск | BMP280 або BME280 (BME280 дає ще й вологість; прошивка розрізняє їх за ID чипа) | I²C 0x76/0x77 |
| Струм/напруга | INA3221, шунти CH1 0.1 Ом, CH2 0.04 Ом, CH3 0.04 Ом | I²C 0x42 |
| RTC | PCF8563 | I²C 0x51 |
| GPS | NMEA, UART (швидкість визначається автоматично: 9600, 115200, 38400) | RX=3, TX=4, EN=5 |
| Дільник батареї | 1.1 МОм до «+», 1.5 МОм до «−» | ADC пін 17 |

Шина I²C: SDA=8, SCL=7.

## Прошивки

| Файл | Роль |
|---|---|
| `Faketec_SX1268_repeater.uf2` / `.zip` / `.hex` | Repeater |
| `Faketec_SX1268_sensor.uf2` / `.zip` / `.hex` | Sensor |
| `Faketec_SX1268_companion_radio_ble.uf2` / `.zip` / `.hex` | Companion (BLE, PIN `123456`) |

Прошивка UF2: двічі натиснути reset → з'явиться USB-диск → скопіювати `.uf2`.
ZIP — для DFU по USB, веб-flasher або OTA (`start ota`). HEX — для програматора.

Радіопараметри за замовчуванням (EU 433MHz Narrow): **433.650 МГц, BW 62.5 кГц, SF 8, CR 8**. Діють при першому запуску; змінюються через `set radio f,bw,sf,cr` або застосунок.

## Що змінено відносно MeshCore

- **SX1268** у варіанті ProMicro (`USE_SX1268`); TCXO лишається увімкненим у standby.
- **Регістр 0x8B5** (`SX126X_REGISTER_PATCH`): недокументований біт для RX/AGC (рекомендація Semtech/Heltec, Meshtastic ставить його на всі SX126x); повторно записується після кожного скидання AGC.
- **Скидання AGC**: чекає завершення калібрування; пропускається, поки йде прийом або є пакет на передачу (раз на добу — примусово).
- **Рівень шуму** не вимірюється перші 50 мс після старту прийому.
- **INA3221**: окремий шунт для кожного каналу; напруга батареї з каналу `TELEM_INA3221_BAT_CH` (2); ознака заряджання за знаком струму (плюс = заряд).
- **АЦП батареї**: множник `ADC_MULTIPLIER` під дільник 1.1М/1.5М, час вибірки 40 мкс. Використовується, поки INA3221 не знайдено.
- **GPS** (код MeshCore `dev`):
  - автовизначення швидкості UART зі списку `GPS_BAUD_PROBE_LIST`;
  - інтервальний режим: вмикається раз на 30 хв (`GPS_PERIOD_DEFAULT=1800`), після fix ще 10 с уточнює і вимикається; якщо fix немає — вимикається через 5 хв (поки після старту не було жодного fix, пошук не обмежений у часі);
  - захист від спуфінгу (`GPS_GUARD`): fix приймається лише при ≥4 супутниках і HDOP ≤ 4.0, у межах регіону (Україна: 44.0–52.5 пн. ш., 22.0–40.3 сх. д.), у межах геозони навколо заданої позиції ноди, без «неможливих» стрибків і після 5 узгоджених fix поспіль;
  - час із GPS пишеться в годинник лише при достовірному fix, у межах [дата збірки; +10 років] і з корекцією не більше 10 хв, а після першої синхронізації — лише в межах дрейфу кварца. Годинник з неправдоподібною датою (наприклад, 2080 рік) виправляється першим достовірним fix;
  - тривога: якщо при достовірному fix GPS довго й стабільно розходиться з годинником, у `gps guard` з'являється `ALERT` (лише в CLI; у телеметрію тривога не йде).
- **CLI**:
  - `telemetry` — показники всіх сенсорів текстом;
  - `time force <epoch>` — виставити час навіть назад (після спуфінгу часу).

## Корисні команди CLI

```
telemetry                    показники всіх сенсорів текстом
power                        батарея / заряджання
clock                        поточний час
time force <epoch>           примусово виставити час (навіть назад)
set lat <..> / set lon <..>  позиція ноди = центр геозони GPS
```

## Команди GPS

Працюють у repeater і sensor; у companion — усі, крім `gps setloc`, `gps advert` і `get/set advert.loc`. Позначка «зберігається» означає, що значення переживає перезавантаження і перепрошивку.

### Стан і керування

| Команда | Що робить | Приклад відповіді |
|---|---|---|
| `gps` | стан GPS: увімкнено чи ні; `active` — зараз шукає/читає, `waiting` — спить до наступного вмикання; кількість супутників і вік останнього fix; режим | `> on, waiting, 12 sats 21s ago, periodic (1800s)` |
| `gps on` / `gps off` | увімкнути / вимкнути GPS (зберігається) | `OK` |
| `gps period` | поточний інтервал у секундах | `> 1800` або `> 0 (continuous)` |
| `gps period <час>` | інтервал вмикання: `30m`, `1h`, `600s`, `1d`; `0` = GPS працює постійно. Заодно вмикає GPS (зберігається) | `OK` |
| `gps once` | позачергово увімкнути GPS і знайти fix, не чекаючи інтервалу; `gps once -s` — ще й синхронізувати час | `OK - waking gps` |
| `gps firstfix` | ліміт пошуку до першого fix після старту, у секундах | `> 3600` або `> 0 (no limit)` |
| `gps firstfix <час>` | змінити цей ліміт: `45m`, `1h`, не більше `1d`; `0` = без ліміту (зберігається) | `OK` |
| `gps sync` | синхронізувати годинник з GPS при наступному fix (з `GPS_GUARD` — лише при достовірному) | `OK` |
| `gps setloc` | записати поточну позицію GPS у `lat`/`lon` ноди | `OK` |

В інтервальному режимі GPS вмикається раз на `gps period`, після fix ще кілька секунд уточнює позицію і вимикається. Якщо fix немає, вимикається через 5 хв; до першого fix після старту — через `gps firstfix` (за замовчуванням 1 год, бо холодний старт буває довгим).

Fix 2D (приймач повідомляє режим у GSA) теж приймається як позиція, але GPS лишається ввімкненим до 5 хв, щоб дочекатися 3D, і засинає лише після 3D. Fix 2D не замінює 3D, молодший за 5 хв.

### Діагностика

| Команда | Що показує | Приклад відповіді |
|---|---|---|
| `gps fix` | останній fix: координати і кількість супутників; якщо fix старий — його вік | `> Fix (12 sat): 50.000000, 36.000000` |
| `gps fix_stats` | час до fix: останній / максимальний; скільки спроб поспіль вдалося (`ok`) і не вдалося (`miss`) | `> ttf:35s/2m ok:3 miss:0` |
| `gps diag` | живлення (`en`), байти UART (`ub`), речення NMEA з правильною (`ok`) і хибною (`bad`) контрольною сумою, супутники, fix, вік даних, режим fix з GSA (`fm`: 1 — немає, 2 — 2D, 3 — 3D, 0 — невідомо) | `en:1 ub:52310 ... ok:812 bad:0 ... sat:12 fix:1 ... fm:3` |

Якщо `bad` росте, а `ok` ні — модуль працює на іншій швидкості UART: додати її в `GPS_BAUD_PROBE_LIST`.

### Захист від спуфінгу

| Команда | Що робить | Приклад відповіді |
|---|---|---|
| `gps guard` | стан захисту: перша частина — позиція, після `time` — час | `> ok 12sat time ok +0s` |
| `gps guard on` / `gps guard off` | увімкнути / вимкнути захист. Вимкнений захист приймає будь-який fix і час, `gps guard` показує `off` (зберігається) | `OK` |
| `gps fence` | радіус геозони в метрах | `> 1000` |
| `gps fence <м>` | змінити радіус; `0` = геозона вимкнена, лишаються межі регіону (зберігається) | `OK` |
| `gps ref` | центр геозони (= `set lat` / `set lon`) | `> 50.000000, 36.000000` |
| `gps guard accept` | при тривозі (`ALERT`) підтвердити, що правий GPS, а не годинник, і записати час GPS у годинник | `OK - clock set from GPS` |

Що означає `gps guard`:

| Позиція | Значення |
|---|---|
| `ok 12sat` | fix достовірний, 12 супутників |
| `settle 2/5` | fix у межах, але ще не набралось 5 узгоджених fix поспіль |
| `no fix 0sat` | модуль не дає fix |
| `rej region` | fix поза регіоном зі збірки (Україна) — спуфінг |
| `rej fence 0.3km` | fix далі за геозону від позиції ноди |
| `rej jump` | «неможливий» стрибок від останньої достовірної позиції |
| `rej sats` / `rej hdop` | замало супутників або погана геометрія (HDOP > 4.0) — слабкий сигнал |
| `off` | захист вимкнено |

| Час | Значення |
|---|---|
| `time ok +1s` | час GPS прийнято, різниця з годинником 1 с |
| `time -` | з GPS ще не приходив час |
| `time wait` | остання перевірка часу пройшла, а свіжого fix зараз немає (GPS спить між вмиканнями) — годинник у порядку |
| `time rej nofix` | час з GPS прийшов, але достовірного fix немає (наприклад, під час спуфінгу) — час GPS не беремо |
| `time rej step 3600s` | GPS розходиться з годинником більше, ніж дозволено |
| `time rej range` | час GPS раніше дати збірки або пізніше за +10 років |
| `ALERT gps-clk +3600s 75m` | GPS 75 хв поспіль стабільно розходиться з годинником на +3600 с: перевірити й за потреби `gps guard accept` (або `time force`, якщо неправий GPS) |

### Позиція в адвертах

| Команда | Що робить |
|---|---|
| `get advert.loc` | поточний режим |
| `set advert.loc none` | не показувати позицію в адвертах |
| `set advert.loc prefs` | показувати задану вручну позицію (`set lat` / `set lon`); за замовчуванням |
| `set advert.loc share` | показувати поточну позицію з GPS |

Стара форма `gps advert [none|prefs|share]` теж працює, але лише коли в збірці є GPS.

Позицію можна не показувати (`set advert.loc none`), залишивши GPS увімкненим для синхронізації часу; задані `set lat`/`set lon` при цьому лишаються центром геозони.

## Збірка

```bash
pio run -e Faketec_SX1268_repeater -e Faketec_SX1268_sensor -e Faketec_SX1268_companion_radio_ble
```

Debug-збірка з логами запуску (I²C-скан, GPS, радіо): `Faketec_SX1268_repeater_debug`.
